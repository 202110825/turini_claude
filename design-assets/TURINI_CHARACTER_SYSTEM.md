# 투리니 캐릭터 조합 구조와 한계

작성 기준: 2026-09-19 · 자산팩 `Turini_Character_Core_Assets` + `Turini_Worn_Previews_v2`

## 1. 무엇을 무엇으로 그리는가

앱 안의 모든 투리니는 **`app/turini-avatar.tsx` 의 `TuriniAvatar` 하나**만 씁니다.
화면마다 이미지를 직접 불러오는 곳은 남아 있지 않습니다.

| 상황 | 그리는 방식 | 액세서리 반영 |
|---|---|---|
| `motion="idle"` (홈·마이페이지·꾸미기·로그인·포트폴리오 안내 등) | **레이어 리그** `turini-rig.tsx` | 모자·안경·목장식·가방 **전부 반영** |
| `thinking` / `correct` / `wrong` / `celebrate` / `reading` | **12프레임 스프라이트** `turini-sprite.tsx` | 반영하지 않음 (아래 3장) |
| 1회 재생(`correct`/`wrong`/`celebrate`)이 끝난 뒤 | 리그로 자동 복귀 | 다시 **전부 반영** |
| 꾸미기 목록 썸네일 / 한 아이템만 보는 미리보기 | 전달받은 **착용 완성본** `worn/*-worn.png` | 그 아이템 하나 (겹쳐 쓰지 않음) |
| 가방 탭 3/4 후면 · 뒷면 | 착용 완성본 + 턴어라운드 | 가방 |

## 2. 리그가 "떠 있지 않은" 이유

`character/rig/` 의 파츠는 모두 1200×1200 같은 캔버스에 그려져 있고,
`rig.json` 이 관절 좌표를 줍니다. 그래서 파츠를 그냥 겹치면 원래 캐릭터가 됩니다.

```
그림자 → 가방 본체 → [몸통 → 다리 → 어깨끈 → 팔] → [머리 → 목장식 → 안경 → 모자]
                                                    └ 머리 그룹: 같은 transform 을 함께 받음
```

- 모자·안경·목장식은 **머리 그룹의 자식**입니다. 고개가 기울면 같은 회전을 받으므로
  화면 위에 따로 떠 있을 수 없습니다. CSS 로 위치만 고정한 구조가 아닙니다.
- 가방 본체는 **몸통 레이어보다 아래**에 있습니다. 구조상 몸 앞으로 나올 수 없습니다.
- 어깨끈은 몸통 위·팔 아래에 그립니다. 팔이 흔들리면 끈이 팔 뒤로 들어갑니다.
- 부착 좌표(`SLOT_ANCHOR`)는 리그를 합성해 **눈·코·입·귀·목·어깨 픽셀 위치를 실제로 재서**
  잡았습니다. 아이템마다 다른 투명 여백은 `CONTENT_BOX` 로 보정해서, 칸이 아니라
  **그림 자체**를 기준점에 맞춥니다.

### 리그가 하는 움직임
숨쉬기(가슴만 부풂) · 고개 미세 기울임 · 좌우 팔 따로 흔들림 · 다리 미세 반동 ·
지면 그림자 호흡 · **3~6초 간격 불규칙 눈 깜박임**.
주기를 4.2s / 5.6s / 3.4s / 3.9s / 4.6s / 5.1s 로 다르게 둬서 기계처럼 맞아떨어지지 않습니다.

눈 깜박임용 머리 그림 2장(`turini-head-blink.png`, `turini-head-blink-half.png`)은
전달받은 `character/face/eyes_closed.png`·`eyes_half.png` 를 리그 머리에 맞춰
**이번 작업에서 파생 생성**한 자산입니다. 원본 자산은 그대로 두었습니다.

## 3. 지금 자산으로 **불가능한 것** (중요)

### 3-1. 정답·오답·축하·읽기·생각 동작에는 액세서리를 붙일 수 없습니다

- 이 다섯 동작은 `turini-animation-atlas-12f.png` 에 **이미 그려진 평면 프레임**입니다.
  프레임마다 머리 위치·크기·각도가 다른데, **프레임별 앵커 정보가 자산에 없습니다.**
- 프레임에서 눈 위치를 자동으로 찾아 보정하는 방법을 실제로 시험했습니다.
  72프레임 중 71프레임에서 눈을 찾았지만, 눈 사이 거리가 44~73px로 흔들리고
  (`thinking` 5번 프레임처럼) 명백히 잘못 잡히는 프레임이 있어 **그대로 쓰면
  모자가 튑니다.**
- 더 근본적으로, 이 동작들은 고개가 3차원으로 돌아갑니다. 정면으로 그려진 모자·안경
  PNG를 돌아간 얼굴에 얹으면 각도가 맞지 않습니다.
- 그리고 이 동작들은 손에 **체크 팻말·X 팻말·책**을 들고 있어서, 영구 손소품과
  자리가 겹칩니다. (그래서 손소품을 영구 슬롯에서 뺐습니다.)

따라서 **현실적인 1차안**을 택했습니다.
정답·오답·축하 동작은 전용 그림 그대로 재생하고, **끝나는 즉시 착용 상태가 반영된
리그 캐릭터로 돌아옵니다.** 부자연스러운 합성을 숨기려고 완성 캐릭터 PNG 한 장으로
대체하는 방식은 쓰지 않았습니다.

### 3-2. 전체 동작까지 반영하려면 필요한 것

다음 중 **하나**가 있으면 모든 동작에 액세서리를 붙일 수 있습니다.

1. **프레임별 앵커 JSON** — 72프레임 각각에 대해
   `{ head: {x, y, scale, rotation}, torso: {x, y, scale}, handLeft, handRight }`
   (아틀라스 한 칸 256×256 기준 픽셀 좌표). 여기에 더해 모자·안경을
   **정면 / 3-4 / 측면** 3종으로 그린 PNG가 필요합니다.
2. **Rive 또는 Spine 리그** — 뼈대에 부착점(슬롯)을 넣은 `.riv` / `.json + atlas`.
   이 경우 12프레임 아틀라스는 더 이상 필요 없고, 모든 동작이 리그로 재생됩니다.
   부착 슬롯 이름은 `hat`, `glasses`, `neck`, `bag_body`, `bag_strap_l`, `bag_strap_r` 를 권합니다.

### 3-3. 그 밖에 요청하면 품질이 올라가는 자산

| 파일 | 왜 필요한가 | 규격 |
|---|---|---|
| `turini-head-noface.png` | 지금 리그 머리에는 눈·입이 **그려져 있어서**, 전달받은 `face/*` 파츠를 위에 얹으면 밑의 눈이 비칩니다. 눈·입이 빠진 머리 한 장이 있으면 입 모양 변화까지 자연스럽게 만들 수 있습니다. | 1200×1200 투명 PNG, 지금 `turini-head.png` 와 **같은 좌표계** |
| `face/` 배치 좌표 | 지금은 눈 픽셀을 재서 맞췄습니다. 정식 좌표가 있으면 더 정확합니다. | `{ eyes: [x,y,w,h], mouth: [x,y,w,h] }` (1200 기준) |
| 가방별 `*-strap.png` | 지금 어깨끈은 가방 그림에서 뽑은 대표 색으로 **CSS 도형**을 그립니다. 실제 끈 그림이 있으면 버클·박음질까지 보입니다. | 512×512 투명 PNG, 가방 9종 각각 |
| `turini-ear_left/right.png` | 귀가 머리 그림에 붙어 있어 "귀만 따로 반동"이 불가능합니다. | 1200×1200, 피벗 좌표 포함 |

## 4. 예외 처리

- 아이템 그림을 못 읽으면 그 아이템만 조용히 빠집니다 (깨진 아이콘 없음).
- 리그 파츠(몸통·머리)를 못 읽으면 **1단계 스프라이트 캐릭터로 통째로 대체**합니다.
- 아틀라스는 WebP → PNG 순으로 미리 받아 두고, 다 받기 전에는 프레임을 숨겨
  로딩 순간에 기본 캐릭터가 잠깐 보이는 일이 없습니다.
- 저장된 아이템 id 가 목록에 없거나 슬롯이 다르면 기본값으로 되돌립니다.
  옛 저장값의 `handProp`·`scene` 키는 무시합니다 (오류 없음).
- `prefers-reduced-motion` 에서는 리그·스프라이트 모두 멈추고 대표 프레임만 보여 줍니다.
